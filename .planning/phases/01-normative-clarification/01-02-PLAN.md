    8.2 Legal Phase/Status Combinations: state that `draft`, `ready`, `active`, and `waiting` are legal at any non-closed phase. State that `done` is legal at any phase as that phase's own local completion signal (gating advancement to the next phase's readiness check), and additionally marks the change's own successful terminal outcome only when it co-occurs with the closed phase. State that `failed`, `cancelled`, and `superseded` are legal only when phase is closed, because reaching any of the three always finalizes the change into the closed phase in the same action.

    8.3 Transition Table: a Markdown table with columns "Action | Legal From (Phase/Status) | Precondition | Gate Order | Resulting Phase/Status | Rejection Behavior", with exactly one row for each of the eight canonical actions from the schema's historyEvent.action enum: start, complete, wait, resume, fail, cancel, supersede, reopen. Every row's Gate Order column restates the existing priority (DoF, then DoW, then current-phase DoD, then next-phase DoR). Every row's Rejection Behavior column states the action is rejected without any partial mutation of persisted state when its precondition or gate is not satisfied.

    8.4 Cancellation, Supersession, Reopening, and Terminal Behavior: new prose, not present anywhere in the current document, defining: (a) cancel — moves any phase/status to closed phase with cancelled status on an authorized cancellation decision; (b) supersede — moves any phase/status to closed phase with superseded status when a later change replaces this change's goal; (c) reopen — moves from closed phase back to the resume phase recorded at closure, or an explicitly stated earlier phase, for corrective follow-up work, and must record the reason and the new goal-bound scope in history; (d) once phase is closed, no further phase advancement is legal except via reopen.

    8.5 Evaluation Priority: carry forward the existing gate-evaluation-order content ("The following order MUST be applied during every gate evaluation: 1. DoF, 2. DoW, 3. DoD, 4. State instead that a change transitions into the closed phase with a terminal status of done — the successful outcome — only when the bulleted conditions that follow are all satisfied, and that the closed phase may also be reached with a different terminal status via the Section 8 rules, which are not gated by this bulleted list. Do not alter the bulleted list itself.
