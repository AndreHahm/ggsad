<objective>
Obtain the repository owner's consent, run the six review passes through Devin CLI, capture each report verbatim, and record the reports and the mechanically derived findings table in the review note. Tracer (task 1): the whole chain up to the first byte is run (pins, snapshot, configuration, authentication, flag parsing, the run-set id) and the consent payload is printed, writing nothing and sending nothing. Task 2 is the consent checkpoint. Task 3 runs the passes one after another, validating each report and the containment of the repository before the next pass, then assembles the note with the script printers, runs the stage reported, and closes the plan.

Purpose: roadmap Phase 4 is a hard gate. Its first success criterion is that a reviewer that is not the Requestor, and not a fresh context or subagent of the Requestor, evaluates the owner-approved diff, and its second that findings carry stable ids, severity and exact references. Independence here is structural: a different product, vendor and model, separate sessions, neutral inputs, a read-only configuration, and a Requestor that only starts the runs and quotes what comes back.

Output: the review note in reported form, one sentence of the diff identity note, a summary.

Shorthand as in 04-01-PLAN.md: SPEC, CHK, CHK2, CHK3, BRIEF, NOTE, ARC, IDN, DEC, REQ, WORK (a `mktemp -d` directory outside the repository, removed at the end of the task that made it, never named in a committed file). MODEL is `swe-2-medium` unless the checkpoint response names another model that the owner chose; in that case MODEL is that name, it must not contain (case-insensitively) `claude`, `fable`, `opus`, `sonnet`, `haiku` or `anthropic`, and it must appear in the output of `devin models list` (a listing call that carries no repository text, made only after the consent).

Flagged assumptions carried from 04-01-PLAN.md (A-1 to A-9) all apply; the ones this plan observes for the first time are A-6 (whether the minimal configuration is honoured: observed only as far as the run authenticates and the repository stays untouched), A-7 (whether standard output is exactly the final message: the first run shows it) and A-9 (the exact headless call). Record what was observed in the summary; an observation does not turn an assumption into a proof.

What follows (described, not pre-written): if every pass is usable, plan 04 asks the owner to disposition each BLOCKING finding (none to ask when the count is 0). If a pass cannot be completed, this plan stops at a checkpoint and the phase stays open; the owner decides whether a later attempt is made, under a new consent.
