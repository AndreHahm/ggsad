<objective>
Obtain the repository owner's consent, run one containment and format pilot and then the six review passes through Devin CLI, capture each report verbatim, and record the reports, the consent trail and the mechanically derived findings table in the review note. Tracer (task 1): the whole chain up to the first byte is run (pins, snapshot, pilot inputs, configuration, authentication, flag parsing, what Devin loads in the inputs directory, the run-set id) and the consent payload and the consent question are composed, writing nothing and sending nothing. Task 2 is the consent checkpoint. Task 3 runs the pilot and then the passes one after another, validating each report and the containment of the repository before the next run, holding the reports and keeping the working directory alive across any stop. Task 4 assembles the note with the script printers, verifies it against the raw output, runs the stage reported, commits, updates the identity note, reruns the Phase 2 and Phase 3 checks and closes the plan.

Purpose: roadmap Phase 4 is a hard gate. Its first success criterion is that a reviewer that is not the Requestor, and not a fresh context or subagent of the Requestor, evaluates the owner-approved diff, and its second that findings carry stable ids, severity and exact references. Independence here is structural: a different product, vendor and model, separate sessions, neutral inputs, a read-only configuration with a pilot that looks for a breach before any real text is sent, and a Requestor that only starts the runs and quotes what comes back.

Output: the review note in reported form, one sentence of the diff identity note, a summary.

Shorthand as in 04-01-PLAN.md: SPEC, CHK, CHK2, CHK3, BRIEF, NOTE, ARC, IDN, DEC, REQ, WORK (a `mktemp -d` directory outside the repository, never named in a committed file; it holds the inputs, the pilot directory, the decoy directory, the throwaway configuration and the captured outputs, and is removed as W2 states). MODEL is `swe-2-medium` unless the checkpoint response names another model that the owner chose; in that case MODEL is that name, it must not contain (case-insensitively) `claude`, `fable`, `opus`, `sonnet`, `haiku` or `anthropic`, and it must appear in the output of `devin models list` (task 1 step 5; a read-only, local listing call that carries no repository text; for a model named at the consent checkpoint it is made again, see task 2 step 3 and task 3 step 1).

Flagged assumptions carried from 04-01-PLAN.md (A-1 to A-9) all apply; the ones this plan first exercises are A-6 (whether the minimal configuration is honoured: not provable; the pilot detects a read that the reviewer reports or that leaks into the output and does not prove the configuration is honoured, and the six passes show only that the repository stays untouched), A-7 (whether standard output is exactly the final message: the report check on every captured output shows it) and A-9 (the exact headless call). Record in the summary what was observed on the six passes; an observation does not turn an assumption into a proof, and the independence residue of A-1 and A-6 is recorded as Unverified (the repository cannot prevent the reviewer from reading outside its working directory if the tool ignores the configuration; it can only detect writes, look for a decoy read in the pilot and ask the reviewer to report what it opened).

What follows (described, not pre-written): if every pass is usable, plan 04 asks the owner to disposition each BLOCKING finding (none to ask when the count is 0). If a pass cannot be completed, this plan stops at a checkpoint and the phase stays open; after a format or tool failure the owner decides whether a re-run is made, under a second consent that names the run; after a containment failure no re-run is offered and the owner decides outside the plan.
