Record the diff identity of the final text of the fix round, put the delta between the text the owner approved in round 1 and the new text to the owner in an approval packet that the script derives wherever it can, ask the owner the questions of the packet through the orchestrator, and record the reply verbatim in a separate record that pins the exact new text. Tracer (task 1): the pins of the final text are read, the diff identity note is updated in place, the new script stage identity checks it against the live text, and the packet skeleton is printed from the pins and the delta; one good run and one seeded defect. Task 2 completes the packet and its checks (stage approval-pending) with seeded fixtures. Task 3 is the owner checkpoint. Purpose: roadmap Phase 4 and requirement APPR-01 (the exact text, as it will be merged, approved by the owner) apply again, because the fixes changed the text that was approved. The owner's approval of the first text is void and stays as history. The fixes are the Requestor's drafting and the owner's decisions (plan 04-05); the owner now approves, or requests changes to, the exact result.

Output: the diff identity note with the new pins, the packet, the record (written only after the reply), the extended script, a summary.

What follows each outcome (described, not pre-written):
- Approved: the record pins the text for the independent review of round 2 (a reviewer that is not the Requestor; a fresh context or subagent of the Requestor is not independent), which plans 04-09 to 04-11 prepare, run and record; this plan does not start it. Any later edit of the specification voids the approval. The tick of APPR-01 that stands in the requirements file since the first round is not changed by any plan; for the new text it rests on this record.
- Changes requested: the phase stays open. A further gap-closure plan (`/gsd-plan-phase 4 --gaps`) edits the specification for the requested changes, the identity is recorded again with the new pins, the packet is regenerated and the owner is asked again; this record stays as the record of this round, and plans 04-09 to 04-11 wait. The tick of APPR-01 that stands in the requirements file since the first round is not changed by any plan and does not describe the live text until a new approval is recorded.
