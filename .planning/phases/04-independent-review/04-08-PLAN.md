Run rules (they restate what plans 04-01 to 04-03 established; those plans give the exact commands and checks). (1) One run is one headless `devin -p` session in mode auto, with the minimal configuration instead of the owner's global Devin configuration, in a throwaway working directory outside the repository, never in parallel, never given the output of another run. (2) The report is ONE file, `REPORT-<id>.md`, which the reviewer creates in one absolute output directory (drive-letter spelling of the path) that is the only place it may write; every other write is denied, and the repository, the decoy directory and the configuration are denied for reads. The captured standard output is not the report and is never checked or quoted. (3) A refused or unapproved tool call ends a headless session silently with no report; therefore the brief states the permitted tools and the real passes ask for nothing else; in the test run the two deliberately refused attempts come after its report is written, and the test run reports nothing about them. (4) Any of these stops the plan at a checkpoint and tells the owner: Devin unavailable, not authenticated, over quota or timed out; no usable output; a report file that fails `--report-file`; an identity that is not Devin; non-empty always-on context beyond the consented residue. There is no fallback to another reviewer, a Claude agent or a self-review. (5) A run may be repeated only when its output was unusable for reasons of format or tool failure (never to obtain a different judgment), at most once per run, and only under a second explicit consent of the owner that names the run; a usable report is never replaced. (6) Any containment failure (the repository changed, the snapshot changed, a file created or changed outside the output directory, an extra entry in the output directory, the decoy token anywhere) offers no repeat: the executor stops at a checkpoint and the owner decides outside the plan; no executor restores anything. (7) When a run fails or Devin stops mid-run, the executor keeps the working directory alive and returns a checkpoint whose payload (for the orchestrator only, never for committed text) names the working directory, lists which runs already have a usable report with the SHA-256 of each held file, and names the run at issue and the kind of problem; the continuation executor reuses the usable reports unchanged, verified by hash and by the report check, and runs only the runs still missing.
